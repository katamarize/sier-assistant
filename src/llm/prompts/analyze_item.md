# 重要度(importance)の判定基準
1〜5の整数で、この新人SIerにとっての「業務への影響度・緊急度・学習価値」を評価する。
安易に3を選ばず、下記の基準に照らして最も近い段階を選ぶこと。中間で迷う場合は、具体的な行動(パッチ適用・技術選定・キャッチアップ)に直結するほど高く、宣伝や個人の感想に近いほど低く倒す。

- 5(最優先 / 今すぐ知り、動く必要がある):
  - 例: 広く使われるライブラリ・フレームワーク(Spring, Log4j 等)やJava/JVM本体の重大な脆弱性(RCE・認証回避)と緊急パッチ、主要クラウド(AWS/Azure)の大規模障害、業務で使う製品のサポート終了(EOL)の確定情報。
- 4(重要 / 直近の業務・技術選定に効く大きな動き。緊急ではないが押さえるべき):
  - 例: Java(LTS)やSpring Bootのメジャーリリース・GA、主要DB・ミドルウェアの新版、広く使われるOSSの重要アップデート、業界の大きな再編・規制動向。
- 3(有用 / 知っておくと役立つ技術動向。すぐ業務は変わらないスキル向上レベル):
  - 例: 一般的な設計・実装のベストプラクティス解説、ツールの中規模アップデート、注目度の高い技術トピックの入門・解説記事。
- 2(参考 / 対象がニッチ、または宣伝色が強く、この新人SIerの業務・学習との関連が薄い):
  - 例: 特定製品のプロモーション、事例紹介中心のPR記事、限られた領域だけの小さな更新。
- 1(対象外 / 業務・学習にほぼ関係しない):
  - 例: 個人の感想・日記、扱う技術領域と無関係な話題、内容の薄い宣伝。

# 出力方針
- summary: 記事の内容を3行以内の日本語で要約する
- beginner_note: この新人SIerの業務・学習にどう関係するかを1文で述べる。直接関係が薄い場合はその旨を書く
- importance: 上記の判定基準に従った1〜5の整数
- tags: 記事に関連する技術・製品・分野のタグ(日本語または一般的な英語表記)
- should_notify: この新人SIerに今すぐ通知する価値があるか(true/false)。重要度が低い、または一般的すぎる内容はfalse
- reason: should_notifyとimportanceをその値にした理由を、判定基準のどの段階(1〜5)に該当するかを含めて簡潔に

出力は指定されたJSONスキーマに厳密に従うこと。JSON以外の文字列は出力しないこと。
