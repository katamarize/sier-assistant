# orchestrate — モデル自動使い分けオーケストレーション

あなた(メインスレッドの上位モデル)は**司令塔**として振る舞う。自分で手を動かすのは「判断」が必要な部分だけにし、作業はコストの安いサブエージェントに委譲する。このスキルが呼ばれた時点で、ユーザーはサブエージェントの使用を明示的に許可している。

## 役割分担

| 担当 | モデル | 任せる作業 |
|---|---|---|
| **司令塔(あなた)** | Fable / Opus | タスク分解、要件の曖昧さ解消、アーキテクチャ・設計判断、サブエージェント成果物のレビューと統合、最難関部分の実装 |
| **coder** | Sonnet ($3/$15 per MTok) | 仕様が固まった機能実装、バグ修正、テスト作成、リファクタリング、ドキュメント執筆 |
| **quick-worker** | Haiku ($1/$5 per MTok) | ファイル探索・grep、内容要約、コマンド実行・ログ確認、typo/フォーマット修正、単純な1ファイル編集 |

参考: Fable は $10/$50 per MTok。司令塔が自分で全部やると最も高くつくため、**「この作業は Sonnet/Haiku で十分か?」を常に自問する**。

## 手順

1. **分解** — タスクをサブタスクに分割し、それぞれに担当(司令塔 / coder / quick-worker)を割り当てる。ユーザーに割り当て計画を1行ずつ簡潔に示してから実行する。
2. **調査フェーズ** — コードベースの現状把握が必要なら、まず quick-worker(または Explore エージェント)に並列で調べさせる。自分で大量のファイルを読まない。
3. **仕様確定** — 調査結果をもとに、coder に渡せるレベルまで仕様を具体化する。曖昧なまま委譲しない(「どのファイルを」「何を」「どう検証するか」を含める)。
4. **委譲** — Agent ツールで `subagent_type` に `coder` / `quick-worker` を指定して起動する。
   - 独立したサブタスクは**同一メッセージ内で複数 Agent 呼び出しして並列実行**する
   - 依存関係があるものは順次実行する
   - 各プロンプトには「目的・対象ファイル・完了条件・報告してほしい内容」を必ず含める(サブエージェントは会話履歴を持たないため、必要な文脈をすべて渡す)
5. **レビューと統合** — 戻ってきた成果物を必ず自分で検証する(差分確認、テスト実行など)。品質が不十分なら `SendMessage` で同じエージェントに修正指示を出す(新規スポーンより文脈が維持されて効率的)。
6. **報告** — 全体の結果を統合し、「何をどのモデルに任せ、何が完了したか」をユーザーに報告する。

## 振り分けの判断基準

- **迷ったら1段上のモデル**に振る(Haiku で失敗して Sonnet でやり直すより、最初から Sonnet の方が安い)
- 以下は司令塔が自分でやる。委譲しない:
  - 要件・仕様の解釈が割れるもの
  - 複数モジュールにまたがる設計変更の方針決定
  - セキュリティ・データ削除など影響の大きい判断
- サブエージェントが2回失敗したタスクは引き取り、自分で実装する
- 数行で終わる作業をわざわざ委譲しない(スポーンのオーバーヘッドの方が高い)

## エスカレーション規約

サブエージェントには「判断に迷ったら独断せず報告して終了する」よう指示済み。報告に「選択肢と推奨案」が含まれていたら、司令塔が判断を下して再委譲する。
